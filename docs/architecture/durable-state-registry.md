# Durable state registry

Each row is one owned location under `{user_root}` unless noted. Kind is source, projection, preference, or compatibility. Recovery is how a reader proceeds when the file is missing or torn.

`read_work_state` takes no path argument. A pointer outside `inbox/work-state/v1/generations` is rejected in Rust and in the Node reader. A pointer whose generations directory is absent reports `malformed`, not `unconfined`: a half-built profile is not an escape attempt.

Every command in `capabilities/default.json` must have a matching entry in `build.rs`, which is what generates `permissions/autogenerated/`. `browser/tests/tauri-manifest.test.mjs` checks the three lists agree, because the native build runs from a mirror outside this checkout and so cannot notice generated files that were never committed.

## Commands that are still generic

`study` and `week_plan` still cross the webview as `{ cmd, params }`. Both are validated before a process spawn (`validate_study_request`, week-plan `PlanError`). They are not the route for new product reads. `read_work_state` is a typed command with no parameters and no path.

Follow-up, one command at a time: replace `week_plan` `show` with a typed read, then each mutation. Do the same for `study` `start` / `submit`. Remove the envelope only when a packaged build no longer needs the adapter.

## Not merged

The registry does not combine study, plan, Canvas, or workspace ownership. Shared atomic write helpers stay in `canvas-store.mjs` (`writeJsonAtomic`) and are imported by the work-state writer. They were not extracted into a new crate.
